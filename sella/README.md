# SELLA

طبقة الصوت والتشغيل داخل سيلترا. المرحلتان صفر والأولى فقط.

## القاعدة المعمارية

سيلا **لا تكلّم Home Assistant**. تكلّم واجهة منصّة سيلترا، والمنصّة هي التي
تكلّم الأجهزة عبر Edge Agent.

```
كلام → سيلا → SYLTRA API → سلسلة السياسة → حاكم السلامة → منسّق الإجراءات → HA → جهاز
```

لو ذهبت سيلا مباشرة إلى Home Assistant لتخطّت السياسة والسلامة، وصار عندنا وكيل
لغوي يصل إلى جهاز من غير البوابة التي بُنيت المنصّة كلها عليها.

## ما الذي يعمل الآن

- ١٢ أداة منزلية للقراءة والتحكّم في الإضاءة والمكيّف والستائر والسيناريوهات.
- بوابة مخاطر: الأقفال والغاز والكهرباء والإنذار خارج متناول النموذج.
- سجلّ تدقيق لكل محاولة، بما فيها المرفوضة.
- نقطة `POST /v1/chat` نصّية، ومزوّدون وهميون يعملون بلا مفاتيح وبلا شبكة.

## التشغيل

```bash
make install
make check      # ruff + mypy --strict + pytest
make run        # http://localhost:8090
```

بلا `.env` يعمل المشروع بالكامل على المزوّدين الوهميين. انسخ `.env.example` إلى
`.env` حين تصير عندك مفاتيح، ولا ترفع النسخة المملوءة إلى Git أبداً.

## ما ليس موجوداً بعد

صوت، ذاكرة، موافقات، أدوات خارجية، واجهة تطبيق. كلّها مراحل لاحقة، ومكتوب في
`PHASE_STATUS.md` ما ينقص كل واحدة وما ينتظر قراراً منك.
